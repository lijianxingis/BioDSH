# 合规准备度

**结论先行：这个项目不具备任何临床或生产环境的合规条件。**

本文不是说要怎么达到合规，是**如实说明差多远**。任何把它读成"接近合规"的说法都是错的。

## 六项硬性条件

| 条件 | 状态 | 差距 |
| --- | --- | --- |
| 预期用途声明 | ✅ 有 | `intendedUse: 'research-only'` 是常量 |
| 临床验证 | ❌ 无 | 从未做过，`clinicalValidationStatus: 'required-not-performed'` |
| 质量管理体系 | ❌ 无 | 没有 QMS，没有设计控制，没有变更控制 |
| 风险管理 | ❌ 无 | 没有 ISO 14971 流程，没有 FMEA |
| 可追溯性 | ⚠️ 部分 | 审计链可自校验，但不防有写权限的人重写 |
| 网络安全 | ⚠️ 部分 | 有边界，但没有认证、没有账号、没有渗透测试 |

## 逐项说明

### 可追溯性：只能算"部分"

审计链能证明**记录之间没有断点**。它不能证明：

- 记录是完整的（中间可以有删掉的运行）
- 记录者是谁（`actor` 可以是 `human-user (identity not verified)`）
- 时间是真的（没有可信时间戳）

在受监管环境里，这三项都是必需的。**有审计链 ≠ 合规追溯。**

### 网络安全：边界存在，认证不存在

有的：

- 医疗模式工具级隔离（宿主强制）
- 容器 digest 钉死、`--network none`
- worker 必须 token，远程拒绝明文 HTTP
- 路径限制在工作区内

没有的：

- 用户认证。**能打开界面的人就能提交决策。**
- 授权模型。角色分离有，但没有和真实身份绑定
- 传输加密的强制
- 任何第三方安全评估

### 没有任何认证

没有 SOC 2、ISO 27001、ISO 13485、CE、NMPA、FDA clearance。

**没有提交过任何一项申请。** 这不是"正在申请"，是"没有开始"。

## 如果要做临床用途

需要的东西按顺序：

1. 明确预期用途和适应人群
2. 建立 QMS（ISO 13485 或等价）
3. 风险管理流程（ISO 14971）
4. 临床验证研究
5. 网络安全评估
6. 监管申报

**任何一步都需要一个组织，不是一次代码提交。**

## 这份文档的用途

防止有人在 issue 里问"这能用于临床吗"，然后被一句含糊的回答误导。

答案是不行。差距是**一个组织和一个临床研究**的量级，不是补几个功能。
