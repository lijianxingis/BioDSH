# 真实运行记录（第二次）

第二次跑的是**完全不同的数据类型**，目的是看第一次的成功是不是特例。

## 数据

DDInter 药物-药物相互作用数据库，肿瘤相关子集。

| 项 | 值 |
| --- | --- |
| 相互作用对 | 65,389 |
| 涉及药物 | 1,699 |
| 级别 | 肿瘤治疗相关 |

## 结果

按相互作用数量排序：

| 排名 | 药物 | 相互作用数 |
| --- | --- | --- |
| 1 | Tacrolimus | 866 |
| 2 | Cyclosporine | 816 |
| 3 | Thalidomide | 785 |

## 关键动作：独立重数

排名出来之后，**用另一条路径把前三名重新数了一遍**，结果一致。

这一步是整个项目里最值得保留的做法：一个数字算出来之后，再算一遍看对不对，
而不是相信第一次的结果。第一次可能是对的，但**没有第二次就不知道它对不对**。

## 两次运行的共同点

| | 第一次（DepMap） | 第二次（DDInter） |
| --- | --- | --- |
| 数据规模 | 430 MB | 65k 关系对 |
| 数据类型 | 数值矩阵 | 关系表 |
| 独立复核 | 泛必需闸门 | 重新计数 |
| 产物 | JSON + 报告 | JSON + 报告 |

共同点不是"都能跑通"，而是**两次都有独立的第二步检查**。

## 这次暴露的问题

第二次运行后做了一轮探测，找到九个真实缺陷，包括：

- 产物登记扫描了整个工作区，而不是只登记声明的路径
- 扫描行数上限静默截断，报告里看不出来
- 续跑时指纹没有覆盖上游产物的实际字节，改了文件仍然复用旧结果
- 已删除的产物仍被当作可用
- 声明的媒体类型没有校验
- `signing/info` 在没有 credentials 服务时崩溃
- 网络策略没有声明
- 计划级的镜像没有钉死

这九个都在重建时带了回来，并各自有测试。
